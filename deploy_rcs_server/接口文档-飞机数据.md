# 飞机数据接口文档（多站点 + 压制干扰版）

> **拓扑**：Python 端作为 TCP 服务端（监听 0.0.0.0:9001），UE 客户端主动连接
> **连接地址**：Python 启动时打印本机 LAN IP，如 `172.22.43.18:9001`
> **字节序**：全部**小端（Little-Endian）**；float32 为单精度，double 为双精度
> **通信模式**：请求-响应循环。UE 每帧发一个请求，Python 回一个单站包（必要时紧跟方向图包）
> **版本**：v2.1（多站 1~4 个雷达站 + 每站独立压制干扰；探测改为雷达方程四次方根定律，协议未变）

---

## 一、UE 传给 Python（请求，可变长度 33+17×N 字节）

> N = 站点数量（1 ~ 4），用 uint8 表示，放在请求头最后一位。
> 每帧请求 = 头 33B + 每站点 17B。

### 1.1 请求头（33 字节）

```
偏移    大小   类型      字段             说明
------  ------ --------- --------------- ------------------------------------------------
0       8      Int64     timestamp       仿真时间，单位毫秒(ms)，原样回传
8       12     float[3]  aircraft_pos    飞机世界坐标 [X,Y,Z]，单位 m
20      12     float[3]  aircraft_rot    飞机姿态 [Pitch, Yaw, Roll]，**角度制(°)**
32      1      uint8     n_stations      站点数量 N（1~4）
33      ───────────────────────────── 站点块从这里开始 ─────────────────────────────
```

> 注意：`aircraft_rot` 顺序为 **[Pitch, Yaw, Roll]**（与 UE FRotator 一致），单位**度**。
> `timestamp` 单位为**毫秒(ms)**（UE 端用 `FDateTime` 毫秒或仿真计数器均可，只需单调递增）。

### 1.2 每个站点块（17 字节，共 N 块）

```
偏移    大小   类型      字段             说明
------  ------ --------- --------------- ------------------------------------------------
0       12     float[3]  radar_pos       雷达世界坐标 [X,Y,Z]，单位 m
12      1      uint8     jammer_on       干扰机开关：0=关，1=开
13      4      float     jam_db_at4km    干扰标定功率：4km 距离处的等效干扰 RCS (dBsm)
17      ───────────────────────────── 下一站点块 ─────────────────────────────
```

> **干扰模型**：干扰等效 RCS σ_jam(R) = σ_jam(4km) × (R/4km)²，干信比 J/S = σ_jam/σ_real
> （干扰单程传播，功率按距离平方增长；R = 本站点到飞机距离）
> UE 演示建议：`jam_db_at4km = -11.5`（迎头 σ≈-13dBsm 时烧穿点约 3.4km），也可按场景任意调整。
> **探测**：UE 无需下发雷达参数；服务端按雷达方程 R_det0 = R_ref·(σ_real/1m²)^(1/4) 动态判定（见第三节）。

**请求完整布局示例（N=2 站）**：

```
[ timestamp int64 ][ pos[3] float ][ rot[3] float ][ n=2 uint8 ]
[ radar1[3] float ][ jam1 uint8 ][ jam_db1 float ]
[ radar2[3] float ][ jam2 uint8 ][ jam_db2 float ]
        总长 = 33 + 17×2 = 67 字节
```

## 二、Python 传给 UE（单站包响应，长度 16+24N+4N(N-1) 字节）

> 每帧响应一个单站包。**先读前 16 字节头**，按 `n_stations` 计算总长再读剩余部分。

### 2.1 响应头（16 字节）

```
偏移    大小   类型      字段             说明
------  ------ --------- --------------- ------------------------------------------------
0       4      Int32     Type            0=仅单站包；1=单站包后紧跟方向图包；2=方向图包自身
4       8      Int64     timestamp       回传请求中的时间戳(ms)，和 UE 发送时间对齐
12      4      Int32     n_stations      站点数量 N（与请求一致）
16      ───────────────────────────── 站点角度块从这里开始 ─────────────────────────────
```

### 2.2 每个站点角度块（16 字节，共 N 块）

```
偏移    大小   类型      字段             说明
------  ------ --------- --------------- ------------------------------------------------
0       4      float     los_theta       视线俯仰角 °（雷达→飞机，与水平面夹角，上正）
4       4      float     los_phi         视线方位角 °（从 +X 起逆时针，0~360）
8       4      float     eff_theta       送入模型的有效入射角 θ °（机体系，0~180）
12      4      float     eff_phi         送入模型的有效入射角 φ °（机体系，0~360）
16      ───────────────────────────── 下一站点角度块 ─────────────────────────────
```

### 2.3 每站点表观 RCS 块（4 字节 × N）

```
偏移    大小   类型      字段             说明
------  ------ --------- --------------- ------------------------------------------------
0       4      float     rcs_apparent_db 该站**表观 RCS** (dBsm) = 物理单站 RCS + σ_jam
4       ───────────────────────────── 下一站 ─────────────────────────────
```

### 2.4 每站点干扰状态块（4 字节 × N）

```
偏移    大小   类型      字段             说明
------  ------ --------- --------------- ------------------------------------------------
0       4      Int32     jam_state       0=未探测；1=压制；2=烧穿；3=正常跟踪（详见第三节）
4       ───────────────────────────── 下一站 ─────────────────────────────
```

### 2.5 双站交叉 RCS 块（4 字节 × N(N-1)，仅 N≥2 时存在）

```
偏移    大小   类型      字段             说明
------  ------ --------- --------------- ------------------------------------------------
0       4      float     sigma_ij_db     σ_ij = 站 i 发射、站 j 接收的双站 RCS (dBsm)
4       ───────────────────────────── 行主序：(1,2),(1,3),…,(1,N),(2,1),(2,3),… ─────────────
```

> **σ_ij 排列规则**：行主序，i 从 1 到 N，j 从 1 到 N，跳过 i==j。
> N=2 时顺序为 [σ12, σ21]；N=3 时为 [σ12, σ13, σ21, σ23, σ31, σ32]，以此类推。
> σ_ij 由"站 i 的近场预测在站 j 的观测方向上取值"计算，供 UE 做双站交叉定位/互易性验证（σ12≈σ21）。

**响应完整布局示例（N=2 站）**：

```
[ Type int32 ][ ts int64 ][ n=2 int32 ]            ← 16 B
[ los1 θ,φ ][ eff1 θ,φ ][ los2 θ,φ ][ eff2 θ,φ ]  ← 16×2 B
[ 表观RCS1 ][ 表观RCS2 ]                           ← 4×2 B
[ jam_state1 ][ jam_state2 ]                       ← 4×2 B
[ σ12 ][ σ21 ]                                     ← 4×2×1 B
        总长 = 16 + 24×2 + 4×2×1 = 72 字节
```

### 2.6 长度速查表（单站包）

| N（站点数） | 单站包总长（字节） |
|---|---|
| 1 | 16 + 24×1 + 0 = 40 |
| 2 | 16 + 24×2 + 4×2×1 = 72 |
| 3 | 16 + 24×3 + 4×3×2 = 112 |
| 4 | 16 + 24×4 + 4×4×3 = 160 |

> UE 接收建议：先 recv 16B 读头 → 得到 n_stations → 再 recv `24N+4N(N-1)` B 补满；
> 若头中 Type==1，继续接收方向图包（见第四节）。

## 三、干扰状态机（jam_state 定义）

| 值 | 名称 | 判定条件 | UE 端展示建议 |
|---|---|---|---|
| 0 | 未探测 | `R > R_det0`（超出雷达对该姿态的探测距离） | 灰/隐藏目标 |
| 1 | 压制 | 干扰开启 且 `J/S ≥ JS_MIN`（默认 1.0 = 0 dB） | 红色"压制"标识；**不要画稳定真实点迹**（雷达被干扰掩盖，只能看到干扰） |
| 2 | 烧穿 | 干扰开启 且 `J/S < JS_MIN`（等价 `R ≤ R_BT`） | 绿色"跟踪"，可画稳定航迹 |
| 3 | 正常跟踪 | 干扰未开启 且 `R ≤ R_det0` | 绿色"跟踪"，可画稳定航迹 |

**说明**：
- 判定顺序：先比距离（超 `R_det0` → 0 未探测），再看干扰是否开启（未开 → 3 正常跟踪），最后比干信比（`J/S ≥ JS_MIN` → 1 压制，否则 → 2 烧穿）。
- **探测距离随目标姿态变化**（四次方根定律，v2.1 起）：`R_det0 = R_ref·(σ_real/1m²)^(1/4)`，
  其中 `R_ref` 为服务端 `--detect-range` 配置的参考探测距离（默认 150km = 对 1m² 目标的探测距离）。
  例：σ=1m²→150km；σ=0.05m²(迎头 -13dBsm)→71km；σ=5m²(侧向)→224km。同一架飞机不同姿态探测距离可差数倍。
- 判定公式（服务端内部）：
  - 干扰等效 RCS：σ_jam(R) = 10^(jam_db_at4km/10) × (R/4000)²   （单程干扰 vs 双程回波）
  - 干信比：J/S = σ_jam/σ_real
  - 烧穿距离：R_BT = 4000 × sqrt(JS_MIN × σ_real / 10^(jam_db_at4km/10))
  - 表观 RCS = 10·log10(σ_real + σ_jam)
- UE 可用"表观 RCS 曲线 + 状态色"同时展示干扰欺骗效果（压制时数值明显偏高）。
- 无效帧（角度越界）所有站 `jam_state = 0`、表观 RCS = -100.0，UE 以 ≤-99 过滤。

## 四、方向图包（24+16×n 字节）

> **触发方式**：单站包头 `Type==1` 表示其后紧跟一个方向图包（UE 无需 select/数帧，按 Type 判断即可）。
> **合成方式**：复用当前帧站点 1 的近场预测做 NFFFT 合成，θ 切面随站点 1 的 LOS 有效入射角**动态变化**（不再固定 90°），φ 步长 10°（37 点）。

```
偏移    大小   类型        字段           说明
------  ------ ----------- -------------- ------------------------------------------------
0       4      Int32       Type           固定 = 2（方向图包自身标识）
4       8      Int64       timestamp      与单站包相同的时间戳(ms)
12      8      double      theta_deg      该方向图对应的切面俯仰角 θ°（= 站点1 当前 eff_theta，动态）
20      4      Int32       n_sample       采样点数量 N（当前 37，φ 步长 10°）
24      8×N    double[N]   PhiDegArr      方位角数组，单位 °，0~360（首尾包含 0 和 360）
24+8N  8×N    double[N]   RcsDbArr       对应每个方位的 RCS (dBsm)，长度 N
```

> UE 接收注意：**两个数组都是 double（8 字节）**，不是 float32——请用 FArrayReader 按 double 读取。

## 五、异常约定

- 帧内任一站点出现以下情况 → **整帧无效**：
  - 飞机/雷达坐标含 NaN/Inf
  - 飞机与雷达位置重合（退化）
  - 有效入射角 θ 越界（模型训练范围 θ∈[30°,150°]）
- 无效帧的响应：所有站点 `rcs_apparent_db = -100.0`，所有 `jam_state = 0`，σ_ij 全部 `-100.0`
- **UE 过滤规则**：`rcs_apparent_db <= -99` 即视为该帧无效，跳过显示。
- 有效帧中，`jam_state` 与表观 RCS 均为可靠数值。

## 六、Type 字段速查

| Type 值 | 含义 | 后续数据 |
|---|---|---|
| 0 | 单站包（仅此一包） | 无 |
| 1 | 单站包 + 方向图包 | 紧跟 24+16n 字节方向图包 |
| 2 | 方向图包自身 | 无（此值只出现在方向图包头部） |

> UE 每帧流程建议：
> 1. recv 16B → 解析头，得 n_stations 与 Type
> 2. recv `24N+4N(N-1)` B → 解析 N 个站点角度/表观RCS/状态 + σ_ij
> 3. 若 Type==1：recv 24B 方向图头 → 得 n_sample → 再 recv `16×n_sample` B → 解析 PhiDegArr/RcsDbArr

## 七、请求/响应对照表（UE 发送 → UE 接收）

```
UE 发送（每帧）                       Python 返回（每帧）
──────────────────────────────      ──────────────────────────────
[ts][pos][rot][n_stations]  ──→     [Type][ts][n_stations]
[radar1][jam1][jam_db1]             [站1: losθ,losφ,effθ,effφ][站2: …]
[radar2][jam2][jam_db2]             [站1: 表观RCS][站2: …]
       …（1~4 站）                  [站1: jam_state][站2: …]
                                    [σ12][σ21][…]（N≥2）
                                    [+ 方向图包]（Type==1 时）
```
