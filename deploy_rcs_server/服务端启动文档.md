# FNO-RCS 推理服务端 · 启动文档

> 适用部署包：`FNO-RCS服务端_部署包.zip`（v2.0，多站点 + 压制干扰）
> 目标：在其他电脑上部署并启动 RCS 实时推理服务，供 UE（Cesium 地球场景）客户端连接。

---

## 0. 启动流程总览

```
①准备环境 → ②解压部署包 → ③安装依赖 → ④启动服务端 → ⑤验证(可选) → ⑥通知 UE 连接
 5 分钟       1 分钟         2~10 分钟      立刻           1 分钟
```

---

## 1. 环境准备（一次性）

**1.1 安装 Python 3.10 或 3.11（64 位）**
官网 https://www.python.org/downloads/ 下载安装，勾选 "Add Python to PATH"。

**1.2 安装依赖库**
打开命令行（Win：`Win+R` → 输入 `cmd`）：

```bat
pip install numpy h5py onnxruntime
```

**GPU 加速（强烈推荐）**——多站批量推理约 150~900ms/批；无 GPU 约 8 秒/帧不可用：

```bat
pip install onnxruntime-gpu
```

GPU 还需 NVIDIA 显卡驱动 + CUDA 12.x + cuDNN（与 onnxruntime-gpu 对应），显存 ≥2GB 即可。

**1.3 验证依赖**（必须打印 OK）：

```bat
python -c "import numpy, h5py, onnxruntime; print('OK')"
```

## 2. 解压部署包

将 `FNO-RCS服务端_部署包.zip` 拷到目标电脑，右键解压，得到目录：

```
deploy_rcs_server/
├── ue_rcs_service.py          ★ 服务端主程序
├── mock_ue_client.py          本地联调模拟客户端（可选）
├── nffft_lite.py              核心库（勿删）
├── F16_demo_trajectory.csv    90s 演示场景（mock 回放用）
├── 接口文档-飞机数据.md        与 UE 的通信协议（勿删，UE 对接用）
├── models/fno_f16_3d_p3.onnx  ONNX 模型
├── data/geometry.h5  stats.npz 模型必要数据
│        calib_affine.json  Δ-分档标定表（2.5 KB，缺失时自动退化为未标定输出）
└── 使用说明.txt
```

**路径要求**：目录中不能有中文/空格路径时可正常使用；若有中文路径一般也兼容，但建议英文路径以避免未知问题。
**勿移动/删除**：`models/`、`data/`、`nffft_lite.py` 与 `ue_rcs_service.py` 必须在同一目录下。

## 3. 启动服务端

**3.1 进入目录并启动**

```bat
cd deploy_rcs_server
python ue_rcs_service.py
```

> 默认单卡模式（自动用 GPU 0）。**多 GPU 机器（如双 3090）推荐双卡并行**，帧率近似翻倍：

```bat
python ue_rcs_service.py --devices 0,1
```

`--devices` 后跟 CUDA 显卡序号（逗号分隔），每卡独立跑一个推理 worker。
先用 `nvidia-smi` 确认本机可用显卡序号（避免选到被桌面/其他程序占满的卡）。

**3.2 启动成功的标志（出现最后一行即就绪）**

```
[标定] 已加载 calib_affine.json：Δ 1.2–146.8° 共 6 节点，b(Δ=0)=0.401 → b(Δ→180°)=0.710
引擎就绪: provider=CUDAExecutionProvider  [GPU0] 表面体素=1346 载入耗时 1.0s
        ↑ GPU 模式（无 CUDA 时显示 CPUExecutionProvider  [CPU]，帧率极低）
[方向图] 动态合成已启用：每 5 帧发送一次，θ 切面随当前 LOS 有效入射角变化，φ 步长 10°（37 点）
[多卡] 启用 1 个推理引擎: devices=[0] （GPU 序号 ['CUDAExecutionProvider/0']）
[探测] 参考探测距离 R_ref=150.0 km @ 1 m²（实际按 R_ref·(σ/1)^0.25 随姿态动态探测）
[干扰] 自屏蔽干扰 J/S=10^(jam_db/10)·(R/4km)²/σ，烧穿判据 J/S<1（R_BT=4km·sqrt(1·σ/σ_jam4km)）
[提示] UE 客户端请连接: 192.168.x.x:9001     ← 记下此 IP:端口
[监听] Python 服务端 0.0.0.0:9001，等待 UE 客户端连接（1 卡并行 worker，Ctrl+C 退出）...
```

（前面还会打印若干 onnxruntime 的 `ScatterND`/节点分配警告，属常规提示可忽略。）

双卡模式会打印两行“引擎就绪”（[GPU0]/[GPU1]）、`启用 2 个推理引擎`，监听行显示 `2 卡并行 worker`。
若首行变成 `[标定] 未加载（...）⇒ 输出为未标定 PO 值`，说明标定表缺失或损坏
（服务仍可正常跑，但精度退化，见 3.5）；加了 `--no-calib` 时该行为提示已关闭。

看到最后一行说明服务已就绪，**此窗口保持开启不要关闭**。

**3.3 UE 端连接地址**
`<本机IP>:9001`
- 本机 IP 用 `ipconfig` 查看（IPv4 地址），或直接用上面日志打印的地址
- 默认端口 9001

**3.4 UE 端请求频率建议**
- 双站实时推理实测：服务端可持续处理约 **8 帧/秒**（输入 125ms/帧、持续 30s 响应 100% 完整）
- 超过 8 fps（如 10/15/20）会积压，响应延迟无界增长
- **推荐 UE 按 200ms（5 fps）固定间隔发送**，RTT 约 250ms 且不积压，留足余量

**3.5 Δ-分档标定（默认开启）**

模型由解析 PO 链路训练而来，PO 在 15λ 电尺寸下对弱散射方向填充不足，误差以「动态范围
压缩」为主（单站口径中位 +5.98 dB，线域总功率仅差 0.68 dB）。`data/calib_affine.json`
给出 `σ_true_dB = a(Δ) + b(Δ)·σ_PO_dB`，其中 Δ 为入射方向与观测方向的夹角：
单站 Δ=0、方向图沿 θs=θi 锥面、双站为双站角；三条输出共用同一张连续表（避免方向图在
φ=φ_i 处与单站结果出现跳变）。

| 口径 | 未标定 med/P90 | 标定后 med/P90 |
|---|---|---|
| 单站（468 角） | 5.98 / 15.82 dB | **3.24 / 7.22 dB** |
| 方向图锥面 | 2.95 / 9.40 dB | 3.00 / **7.07 dB** |
| 全方向池化（468×2701） | 3.16 / 8.97 dB | **2.82 / 7.07 dB** |

判决级收益（交叉验证）：R_det 相对误差中位 29.6%→18.1%、R_BT 52.0%→35.3%、
四态判决不一致 15.5%→7.9%。

标定文件缺失或加 `--no-calib` 时自动退化为未标定输出，并在日志中提示。

## 4. 常用启动参数

| 参数 | 说明 | 示例 |
|---|---|---|
| `--port N` | 改监听端口 | `python ue_rcs_service.py --port 9002` |
| `--host IP` | 仅监听指定网卡（默认 0.0.0.0 全部） | `--host 127.0.0.1` 仅本机调试 |
| `--pattern-every N` | 方向图每 N 帧发一次（默认 5，0=不发） | `--pattern-every 3` |
| `--devices 0,1` | 多卡并行：每卡一个推理 worker（默认 `0` 单卡） | `python ue_rcs_service.py --devices 0,1` |
| `--max-samples N` | 每批最多 ONNX 样本数（默认 8；显存不足可调小至 4/2） | `python ue_rcs_service.py --max-samples 4` |
| `--selftest` | 自检模式：验证模型/管线，不启动监听 | `python ue_rcs_service.py --selftest` |
| `--no-calib` | 关闭 Δ-分档标定（默认开启，见 3.5） | `python ue_rcs_service.py --no-calib` |

## 5. 验证服务正常（推荐，无需 UE）

**方式 A：自检**（十几秒，验证模型与物理管线）

```bat
python ue_rcs_service.py --selftest
```
打印 `自检通过` 即环境与模型完好。

**方式 B：本地模拟 UE 回放 90s 对抗场景**（开两个终端）

```bat
:: 终端 1：启动服务端
python ue_rcs_service.py

:: 终端 2：回放演示场景
python mock_ue_client.py --host 127.0.0.1 --port 9001
```

终端 2 应实时打印两站表观 RCS / 干扰状态 / σ12σ21（t≈41s 站1 从 -5dB 跳到 -0.4dB 进入"压制"，t≈80.6s 进入"烧穿"），说明整条链路正常。

## 6. 停止服务

- 直接 `Ctrl + C` 关闭。
- 需要长时间运行时，可后台启动（PowerShell）：

```powershell
Start-Process python -ArgumentList "ue_rcs_service.py" -WindowStyle Hidden
```

## 7. 网络与防火墙（UE 连不上时检查）

1. 服务端与 UE 须在同一局域网。
2. 防火墙放行入站 9001 端口（管理员 PowerShell）：

```powershell
netsh advfirewall firewall add rule name="RCS9001" dir=in action=allow protocol=TCP localport=9001
```

3. 确认 UE 填的是服务端打印的局域网 IP（不是 127.0.0.1），端口 9001。
4. 可用 `telnet <服务端IP> 9001` 或 mock 客户端（方式 B）验证端口可达。

## 8. 故障排查速查表

| 现象 | 原因与处理 |
|---|---|
| 打印 `CPUExecutionProvider` | 未装 onnxruntime-gpu / 无 CUDA，帧率会极低；装 GPU 版 |
| 提示缺 onnxruntime 等模块 | 依赖未装齐：`pip install numpy h5py onnxruntime` |
| UE 一直连不上 | 看第 7 节：防火墙、IP、端口、是否同一网段 |
| UE 收到 RCS=-100 的帧 | 该帧站点角度越界(θ 超 30°~150°)，属正常过滤；检查飞机-雷达相对位置 |
| 干扰不生效（状态非"压制"） | 请求该站 jammer_on=1 且 jam_db_at4km 合理（如 -11.5）；需距离<11.9km |
| 日志出现 ScatterND 警告 | onnxruntime 常规提示，可忽略 |
| 自检失败 | 检查 `models/`、`data/` 是否在程序同目录、文件是否完整 |
| 打印 `[标定] 未加载` | `data/calib_affine.json` 缺失/损坏：精度退化为未标定 PO（单站中位 5.98 dB），补回该文件即可；对比测试可用 `--no-calib` |
